# ドキュメント構成

このフォルダには、AI駆動開発を効率化するためのドキュメントが格納されています。

## 📂 各ファイルの役割

### `requirements.md` - 要件定義書
**いつ使う？**  
新しい機能を追加・修正する前に、AIに「何を作りたいか」を明確に伝えるため

**記載内容**
- 実装する機能の目的
- 実装範囲・実装しない範囲
- 受け入れ条件（完了の定義）

**使い方**
1. 新機能を追加する前に記入
2. AIに「`@docs/requirements.md` を参照して実装してください」と依頼
3. 実装後、受け入れ条件をチェック

---

### `decisions.md` - 技術判断ログ
**いつ使う？**  
「なぜこの方法を選んだのか？」を後から思い出すため

**記載内容**
- 技術選定の理由
- 採用した方法と却下した方法
- 判断の背景

**使い方**
1. 実装方法で迷ったとき、AIと相談
2. 決定した内容をログとして記録
3. 後で「なぜこうしたんだっけ？」を防ぐ

---

### `tasks.md` - タスク管理
**いつ使う？**  
大きな機能を小さく分割して、進捗を見える化するため

**記載内容**
- 実装タスクの一覧
- 各タスクのステータス（未着手/作業中/完了）
- 気づきやメモ

**使い方**
1. 大きな機能を小タスクに分割
2. 1つずつAIに依頼して進める
3. 完了したら✅にして次へ

---

## 🎯 AI駆動開発の流れ（推奨）

```
1. requirements.md に「何を作るか」を記入
   ↓
2. tasks.md に小タスクへ分割
   ↓
3. AIに「@docs/requirements.md と @docs/tasks.md を見て、タスク1を実装してください」
   ↓
4. 実装完了後、動作確認
   ↓
5. tasks.md のステータスを更新
   ↓
6. 技術的な判断があれば decisions.md に記録
   ↓
7. 次のタスクへ（2に戻る）
```

---

## 💡 初心者向けアドバイス

### ドキュメントは「完璧」を目指さない
- 最初は箇条書きでOK
- 実装しながら追記・修正していく
- 「後で見返してわかる」レベルで十分

### AIへの依頼の仕方
- ❌ 悪い例：「お問い合わせフォームを作って」
- ✅ 良い例：「`@docs/requirements.md` を参照して、`@docs/tasks.md` のタスク1を実装してください」

### 小さく進める
- 一度に全部作ろうとしない
- 1タスク = 1〜2時間で終わる単位
- 動作確認してから次へ

## 🔄 メンテナンス

- プロジェクト終了後も残しておくと、次回の参考になる
- 「なぜこうしたか」の記録は将来の自分への贈り物
