### 判断日：2026-01-19
#### 判断内容
WordPress バージョンの選定

#### 採用した方法
WordPress 6.5.5-ja（日本語版）

#### 理由
- 2024年リリースの安定版で、学習用として十分な機能を持つ
- 日本語版を使用することで、管理画面が日本語で扱いやすい
- .wp-env.json で明示的にバージョン指定することで環境の再現性を担保

#### 却下した選択肢と理由
- 最新版（常に latest）：バージョン固定しないと環境の再現性が損なわれる
- 英語版：学習者が日本人のため、日本語版を優先

### 判断日：2026-01-19
#### 判断内容
問い合わせフォームの実装方法

#### 採用した方法
Contact Form 7 プラグインを使用

#### 理由
- WordPress で最も普及している問い合わせフォームプラグイン
- 初心者でも管理画面から簡単に設定できる
- .wp-env.json で自動インストール可能
- セキュリティ・スパム対策もプラグインで対応可能

#### 却下した選択肢と理由
- 自作フォーム（PHP）：セキュリティ対策・バリデーション実装が複雑で学習コストが高い
- WPForms など他のプラグイン：Contact Form 7 の方が情報量が多く学習しやすい

### 判断日：2026-01-19
#### 判断内容
開発環境の起動コマンド

#### 採用した方法
`npm run start` で wp-env + Gulp を同時起動

#### 理由
- 1コマンドで開発環境が立ち上がるシンプルさ
- README.md にも記載済みで、初心者が迷わない
- package.json の scripts で `npx wp-env start && npx gulp` として定義

#### 却下した選択肢と理由
- `npm run dev`：一般的だが、既存の package.json が `start` を使っているため統一
- 個別起動（wp-env と gulp を別々に）：手間が増えて初心者に不親切

### 判断日：2026-01-19
#### 判断内容
テンプレートファイルの最小構成

#### 採用した方法
MVP では index.php をフォールバックとして使用し、single.php / archive.php / page.php は将来実装

#### 理由
- WordPress のテンプレート階層により、index.php があればすべてのページが表示可能
- 最小限のファイルで動作確認でき、学習コストを下げる
- 機能追加時に必要なテンプレートを段階的に作成できる

#### 却下した選択肢と理由
- 最初から全テンプレート作成：MVP には不要で作業量が増える
- index.php のみで完結：将来的な拡張性を考慮してテンプレート分割は計画に残す

#### 判断内容
CI/CD・自動テストの扱い

#### 採用した方法
MVP では未実装、将来機能として要件定義に記載
